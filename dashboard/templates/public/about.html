How this works

The Competency Recommender pipeline turns real Indonesian software-and-game-development job postings into actionable curriculum recommendations, aligned with KKNI (Indonesia's national qualifications framework, Perpres 8/2012).

1. Where the data comes from

Job postings are scraped continuously from public job boards. Postings are deduplicated, language-detected, translated where needed, and split into sentence-level units while keeping the source job_id and job_date attached to every sentence.

2. How skills and knowledge are extracted

An LLM reads each posting end-to-end and produces a structured JSON list of hard skills, soft skills, and knowledge items. JobBERT (a fine-tuned span tagger) is retained as an ablation path but is no longer the default. Each skill carries a Bloom level (Remember → Create) and a confidence score.

3. How competencies are generated

Hard skills are clustered by future-of-work domain (sourced from WEF, O*NET, and McKinsey reports) and grouped into thematic batches. The LLM converts each batch into 8–12 competency statements. Each competency carries:

  • A Bloom level (highest among related skills)
  • A KKNI level 1–9, derived deterministically from Bloom + LLM judgment within a clamped band
  • A list of soft skills required grounded in extracted soft skills + LLM expansion

5. Curriculum upload format

The coverage analyzer accepts:

  • CSV with a column named one of: phrase, phrases, objective, objectives, content, topic, name, title, description. Multiple values may be comma- or semicolon-separated within a cell.
  • JSON / JSONL — any nested object. We walk the tree and collect string values whose key matches the same field names above.

Tip: even a flat list of subject names like ["Algoritma","Basis Data","Jaringan"] works — we'll do fuzzy matching against competency titles and related-skill lists.

6. Limitations

  • The current corpus is English-language only, used for prototyping. Indonesian-language postings are queued for a follow-up pass.
  • Coverage analysis uses substring + normalized-token matching, not deep semantic matching, so a curriculum entry like "OOP" may miss a competency phrased as "Object-Oriented Programming".
  • KKNI levels are constrained to a Bloom-derived floor band (floor or floor+1) to avoid LLM over-reach. Edge cases involving high-craft Create-level competencies at low education stages may need expert review.
